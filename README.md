# MR Web Lab

A creative and technical laboratory for designing, developing, prototyping, and documenting websites before their implementation in WordPress.

## Purpose

MR Web Lab is where website ideas become considered visual systems and working prototypes. Each project moves through visual direction, UX/UI decisions, front-end development, testing, and—when appropriate—implementation in WordPress.

## Project architecture

**Every website has its own GitHub repository.** This keeps its code, issues, version history, documentation, and deployment independent.

This repository is the central hub for the lab. It contains:

- Shared methodology and project workflow.
- Reusable resources and technical notes.
- Experiments that are not yet part of a specific website.
- An index of the individual website projects.

## Workflow

1. **Brief** — define the business, audience, goals, scope, and constraints.
2. **Art direction** — establish visual identity, references, typography, color, and imagery.
3. **UX/UI** — define page structure, content hierarchy, and responsive behavior.
4. **Prototype** — build a functional front-end using the simplest suitable technology.
5. **Review** — test usability, responsiveness, accessibility basics, and visual consistency.
6. **Publish demo** — deploy eligible static prototypes with GitHub Pages.
7. **WordPress implementation** — translate the approved design and functionality into WordPress when required.

## Technology principles

- Start with semantic HTML, CSS, and JavaScript.
- Introduce React or other frameworks only when the project benefits from them.
- Design data structures with the future WordPress implementation in mind.
- Keep prototypes independent from production credentials, private data, and client systems.
- Document important decisions so each project can be continued and maintained.

## First project

**Raíces Traslasierra** — a locally oriented real-estate website concept for Traslasierra, Córdoba, Argentina. Its source code will live in its own repository.

## Publishing

GitHub Pages can host static prototypes (HTML, CSS, and client-side JavaScript). It does not run PHP, a WordPress installation, or a database. WordPress implementations require a suitable hosting environment.
